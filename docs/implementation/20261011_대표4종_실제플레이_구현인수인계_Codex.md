## 1. 현재 실행본

기획서의 초기 계약을 실제 플레이 코드로 구현한 확장본이다. **활성 코드는 `src/arcadeComplete/`, 활성 전투 표는 `assets/arcade/config-codex/`**다. `src/arcade/`와 `assets/arcade/config/`는 Claude가 만든 이전 단계 보존본이다. 현재 HTML은 새 실행본을 가리킨다. 이전 코드에서 game2~4가 미구현으로 보이더라도 현재 실행본 상태와 혼동하지 않는다.

- 기획툴: http://localhost:4174/planner/#play
- 제작실 전체 화면: http://localhost:4174/planner/play.html
- 캠페인 로비: http://localhost:5190/arcade-lobby.html
- 독립 실행 목록: http://localhost:5190/arcade.html

### 실행

PowerShell에서 다음 명령을 실행한다. 기존 서버가 정상 동작하면 재사용하고, 빈 포트일 때만 창을 숨겨 서버를 시작한다.

```powershell
& 'C:\soos-arcade\tools\start-arcade-complete.ps1' -OpenBrowser
```

Vite 5190과 planner 4174 두 서버를 사용한다. `file://`로 HTML을 여는 방식은 사용하지 않는다. 예전 5180 마을 서버에 의존하지 않는다. 실행 로그는 `docs/playtests/runtime/`에 남는다.

공통 구조는 입력/고정 틱, 판정/성장, 3D 표시/연출, 캠페인/저장, 제작실/설정이다. 별도의 간이 시뮬레이터를 실행하지 않고 같은 게임을 제작실 iframe과 독립 HTML에서 실행한다. 과거 10종 시뮬레이터와 문서는 기록으로 남겼으며 이번 플레이 대상으로 대표 4종을 사용한다.

### 조작과 첫 판

- 코어 방어: 빛나는 칸 선택 → 비용 확인 후 설치 → 전투 시작. WASD/방향키 또는 드래그로 이동한다. 준비·다음 웨이브마다 시설을 개량한다.
- FPS: 준비 화면은 탑다운, 전투는 1인칭. 왼쪽 터치로 이동하고 오른쪽 터치로 시점을 돌린다. 두 손가락을 동시에 사용할 수 있다. 시야 중앙 18도 내의 가까운 적을 자동 공격한다. 시작 방향은 코어 정면을 피해서 길을 보게 했다.
- 대생존: 이동 회피와 XP 회수로 성장한다. 레벨 선택 중에는 판정이 정지한다. 무기 Lv5와 짝 패시브 조건을 만족하면 진화 카드가 나온다. 마지막 보스를 실제로 처치해야 승리한다.
- 체인: AD/좌우 드래그. 포인터를 월드의 목표 X로 바꾸어 이동한다. 숫자를 깎아 마디를 제거한다. 경계 도달 판정이 그 틱의 사격보다 먼저여서, 같은 틱에 선을 넘은 적을 쏴서 패배를 취소할 수 없다.
- 튜토리얼: 시작·성장·준비·보스·FPS의 안내. 이번 판 안내 끄기 가능. 최초 안내의 확인만 브라우저에 저장한다.

### 중요한 수정

1. FixedClock.resume가 매 프레임의 `resume('card')` 호출마다 시계를 초기화하던 결함을 고쳤다. 실제로 제거된 pause 사유가 있을 때만 초기화한다. 이 문제는 판정 가속만 돌리는 검사로는 발견되지 않았고 실제 입력으로 확인했다.
2. FPS 이동을 카메라 방향 기준으로 바꾸고, 스킨 변환한 **총 전체의** 경계 상자를 다시 계산해 두 권총의 크기를 정했다. 하위 메시마다 따로 크기를 맞추면 총 형태가 깨진다. 원본 캐릭터의 얼굴·총·납도 상태를 전체 traverse로 강제 표시하지 않는다.
3. 드론 탄 방향을 인간 위치 대신 각 드론 발사 위치에서 계산한다. 고정 표적 검사에서 빗나가던 두 드론이 실제 피해를 준다.
4. 화염 장판은 발사한 기술의 합성 값과 sourceSkill을 보존한다. 화상은 0.5초 간격 × DPS로 계산하고 같은 종류는 강한 값만 유지한다.
5. 죽은 적의 아직 발동하지 않은 예고 공격을 취소한다. 피해 표시도 실제 적용 피해를 사용한다.
6. 시험/리플레이/디버그 결과는 캠페인 별·미션·구조 펫을 바꾸지 않는다. 제작실에서 나갈 때도 시험 카드 메뉴로 돌아간다.

## 4. 활성 데이터와 편집

`assets/arcade/config-codex/`가 실행 정본이다. `data/handoff-baseline.v2.json`은 이전 설계/검토 기준이며 현재 밸런스 값을 덮어쓰는 파일이 아니다.

|---|---|
| common.json | 틱·인간 HP/속도/크기·성장 슬롯·XP·전투 펫 |
| rulesets.json | 코어/시설/웨이브·출발 장비/300초 생존/보스·체인 탄수/간격/경계 |
| profiles.json | 4프로필·상속·FPS 카메라/입력·프로필 override |

| enemy-catalog.json | 49종 원본 모델·HP·속도·피해·갑옷·역할·특수 행동 |
| behavior-contracts.json | 역할별 지원/회복/돌격/잠복/수중/공중/사격/방패 등 실시간 값 |

| maps.json | 새 3D 맵과 내비 자료·실제 좌표/경로 |
| campaign.json·lobby.json | 20미션·선행 잠금·구조 펫·지역 combatTuning·마을/출항·시간 변화 |
| presentation.json | 피해/파편/카드/튜토리얼 표시 계약. 소리는 이번 범위에서 제외 |

`encounter-plan.json`은 자산 배치 참고다. 실제 스폰은 spawn-plans의 regional 자료를 사용한다. 49종이 5지역에 나누어 연결되며 한 판에 49종을 전부 무차별 생성하지 않는다. 역할과 지역 HP/속도/피해 배율이 적용된다. 수중 2종은 대생존의 실제 연못에 배치한다. 시설만 모드에서 물 밖에 고정된 적 때문에 웨이브를 끝내지 못하는 배치를 피했다.

기획툴의 숫자 입력은 해당 판 override, 설정 저장은 선택한 지역·미션의 params 차이값만 campaign에 남긴다. 공통 기본값은 rulesets/common/skills에서 바꾸고 지역 combatTuning의 보급/배율을 거쳐 적용된다. 수치 입력은 지역의 현재 실제 값을 표시하며 실행 준비 메시지가 편집 중인 값을 초기화하지 않는다. 전체 JSON과 공통/적/스폰 등의 표도 편집 가능하다. 저장 시 서버 검증 후 임시 파일과 백업을 사용한다. 음수 인간 HP 저장은 HTTP400으로 거절하는 것을 확인했다. 백업: `docs/playtests/config-backup/`.

주의: 배열은 전체 교체, 객체는 키별 병합이다. 0/false도 값이다. 미션의 프로필과 요청 프로필이 다르면 실행 전에 거절한다. 보스 절대 HP에 지역 배율은 한 번만 곱한다. 전투 중 표를 저장해도 실행 중인 불변 스냅샷은 바뀌지 않고 다음 실행에 적용된다.

### 몬스터 행동

- 일반 근접·방벽 유인/접근 슬롯·코어 우선·돌격·예고 후 원뿔 공격.
- 원거리의 실제 탄, 부채꼴 3/5발·저격 선 예고·도탄·느린 투사/장판.
- 측면 접근·회전 접근·일시 질주·예고한 잠복/위상 이동. 잠복 중에는 피해와 표적 획득을 막는다.
- 공중 고도와 경계 보존, 수중은 실제 연못 내부에 머문다. 연못은 보행을 막지만 총알의 LOS를 막지 않는다.
- 지원은 가까운 제한 수의 동료에게 비중첩 속도 효과, 회복은 대상별 3회까지만 하고 보스는 제외.
- 전방 방패는 실제 앞/뒤 피해가 다르다. 펫 구속은 시간 만료나 시전자 사망으로 풀리고 다른 구속이 시간을 계속 늘리지 않는다.
- 체인은 이러한 자유 AI 대신 편대의 고정 순서와 간격을 유지한다. 예전 g09용 바닥 칠하기와 수레 등 제거된 게임 전용 계약은 이번 대표 4종의 기능으로 표시하지 않는다.

## 5. 리소스 재사용과 맵 제작법

기존 3D 리소스는 `assets/susu/`와 `assets/village/releases/VILLAGE03/`에서 읽는다. 캐릭터/펫 GLB의 디자인을 바꾸지 않았다. 루온·리아 각각 기본/3.5등신, 전투 펫 5종, 복셀 몬스터 49종, 기존 포탑/텐트/나무/바위/상자/울타리/표지/크리스털을 재사용한다.

### 새 맵

출력: `assets/arcade/maps/CODEX_FOREST/`

| 맵 | 크기 | 배치 |
|---|---|---|
| defense | 42×52m | 3진입로+보스 진입·중앙 코어 광장·4건설 칸·숲/연못/캠프/표지 |
| survival | 38×44m | 회피용 넓은 통로·중앙 교차 길·실제 나무/바위 장애물·연못 |
| chain | 보드12×24m | 별도 숲 섬 위의 체인 보드·좌우 경계·붉은 최종 방어선 |

각 맵에 polluted/purified GLB 두 상태, navigation JSON, Blender preview가 있다. 지형 높이는 새로 제작한 보행 평면 0m이며 장식/나무/연못은 같은 저작 자료로 충돌을 정한다. 이 맵을 옛 공중섬의 다층 내비로 취급하면 안 된다. 로비의 공중섬 생활은 별도의 기존 NavGraph를 유지한다.

Blender 원본/생성 스크립트: `art-source/arcade/CODEX_COMPLETE/`.

1. `build_arcade_maps.py`는 기존 units_free dense 블록 표본을 읽고 노출된 면만 만들어 지형/건물/소품을 조합한다. 원본은 바꾸지 않는다.
2. 바닥은 0.5m 격자. 묻힌 내부 면은 만들지 않고 재질 팔레트로 합친다. 나무·시설·캠프·연못·길과 내비 장애물을 함께 저작한다.
3. 1차 후 다시 검수하여 바닥 색·겹친 길·숲 볼륨을 정리했다. 추가 검수에서는 길 가장자리 풀·돌·꽃, 시설 받침의 모서리와 광장 무늬, 체인 보드의 옅은 격자·등불/크리스털을 보강했다. 지면과 수관/큰 소품을 별도 메시로 묶어 수관만 실제 그림자를 드리운다. 색은 glTF용 선형 값으로 내보낸다.
4. 공유된 원본 메시를 join하기 전 활성 객체의 data를 copy한다. 이를 생략하면 캐시의 나무 하나가 이전 맵의 모든 나무로 변해 다음 맵이 커지는 오류가 생긴다. 최종 GLB는 방어 약9.3MB·대생존9.9MB·체인5.4MB다.
5. 실제 게임은 동일 GLB를 로드한다. FPS의 하늘은 로비의 VillageSky 복셀 구름·태양·하늘을 재사용한다. 전투 카메라는 게임 목표에 맞춰 방어/추종/보드/FPS로 나눈다.
6. `.blend`와 이전 `.blend1`은 art-source에 보관하고 런타임 폴더에는 배포/조회용 자산만 둔다.

## 6. 성능과 자원 수명

- 복셀은 Greedy Mesh와 캐시. 게임 프레임마다 모델을 다시 복셀화하지 않는다.
- 대생존은 종별 인스턴스. 가까운 소수/보스는 30칸, 밀집 또는 먼 일반 적은 14칸 모델을 사용한다.
- 150마리 고정 장면의 삼각형은 약220만→725,600개, draw call 73회로 줄었다. 이 숫자는 브라우저 renderer.info의 그리기 수치이며 실제 휴대폰 FPS가 아니다.
- 탄/구슬/파편은 인스턴스, 파편256·피해 숫자48 상한. XP 상한160을 넘으면 가까운 구슬에 값을 합쳐 XP를 보존한다.
- 해제 시 RAF·입력/resize/blur/포인터/visibility 처리·mixer·geometry/material·WebGL context를 정리한다. 오래된 시설/모델 비동기 로드가 해제된 화면에 붙지 않도록 확인한다.
