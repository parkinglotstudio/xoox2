# 제작 AI에게 전달할 프롬프트

아래 내용을 프로젝트 `C:\soos-arcade`에 접근 가능한 제작 AI에게 전달하세요. 전체 문서 패키지를 함께 제공해야 합니다.

---

당신은 수스 아케이드의 3D 본 게임 제작 담당이다. 작업 루트는 로컬 `C:\soos-arcade`다. 기존 수스 `C:\xoox`와 CodexPack 복사본을 작업하지 않는다. 커밋·푸시는 내가 명시적으로 요청할 때만 한다. BOARD에서 자기행만 갱신하고 날짜·담당자 이름의 보고와 실제 스크린샷을 남긴다.

먼저 `docs/plans/20261011_3D제작명세_Codex/00_제작기획서_Codex.md`와 연결된 01~06문서, data/초기값·리소스·웨이브·검증 결과를 모두 읽어라. 최신 기존 기획 정본 `planner/data.json`도 확인한다. 오래된 README의 6장·미복사설명, 예전 2D시뮬레이터의임시수치를그대로제작기준으로삼지마라. 새패키지의숫자는제안초기값이며플레이검증된최종값이아니다. 문서간충돌은작업시작전에구체적필드/값/근거를기록해해결한다.

제작할것은 **공통 구조 5종을바탕으로게임 10종전체,3D공중마을로비,카드미션로비,결과·구출·귀환**이다. 기획툴에서각파트를독립실행/조절/플레이/기록하고연결플레이도가능해야한다. 기획툴의실행화면을간략 2D시뮬레이션으로만들지말고본 게임과같은 3D런타임을쓴다. 나중에게임에붙일때규칙을재구현하지않도록scene/session/config/storage/bridge를분리한다.

기존 3D리소스를최대한재사용한다. 루온/리아두비율,펫 5종,복셀몬스터 45+UFO4,복셀시설·캠프·기계·수목·바닥·무기/FX,Claude의미션맵과VILLAGE03이기준이다. 부족한모션·리그·내비·충돌·셀맵·게임데이터만추가한다. 기존얼굴/머리/옷·펫디자인을임의로다시만들지않는다. 사용 안 함 2D스프라이트/그림과기본 구체적을실제게임자산으로쓰지마라. Blender가필요하면원본을보존하고추가본을편집해.blend/GLB/스크립트/소켓·배치·렌더를함께남긴다.

**첫 작업은 M0→M1→M2다.**

1. 실제경로·버전·자산·클립·좌표/고도를검증하고이번제작범위와파일변경계획을작성한다.
2. 04문서의제안폴더·계약을초기구조로만들고,고정 60틱·입력·배우·내비·로딩·UI·로그·해제·기획브리지를붙인다.
3. g05를전투 1~3/등대·보조시설/적분산/카드/실패·결과까지실제조작으로완성한다. 직접 공격은빠르게,폭탄·투석기는느린범위타격. 혼합 종류는동시다른길·다른속도로온다. 시간만지나면성공하는가짜규칙은없다.
4. 마을보관코드를아케이드로이식하고로비→카드→출항→g05→결과→귀환을연결한다. 외부 5180제작서버없이이프로젝트에서실행한다.
5. M3이후순서로 10종을확장한다. 임의미완료스텁이나자동성공을완료로 보고하지 않는다. 각게임은 02의승패·모션·예외·검수조건을충족해야한다.

밸런스는data초기값을출발점으로하고무적없는실제 플레이/고정seed/측정지표로조정한다. 첫 바퀴펫없음, 방 20, 웨이브 8,층 5,보스 3단계,정화 70%,러너약 720m의기준을유지한다. 설정은구조화하고기획툴편집→검증→snapshot→실행→결과→기준판승격흐름으로저장한다. 캠페인결과와무적/봇/개발수정테스트를분리한다.

작업중다른AI변경을덮어쓰지마라. 큰 설계변경·범위추가가필요하면현재증거/선택지/권장안을문서로제시한다. 결과 보고는완료 기능·미완료·실행 방법·실제 자산·설정 해시·정상/실패/재시작기록·스크린샷·다음단계를포함한다. 파일만생겼다고게임플레이완료로말하지마라.
