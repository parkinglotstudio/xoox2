# 공통 런타임·로비·기획툴 상세 명세

작성: Codex · 2026-10-11 · v2  
아래 숫자는 제작 초기값이다. `data/common.v2.json`과 `data/rulesets.v2.json`이 값을 구조화한다. 프로필의 명시적 덮어쓰기가 공통값보다 우선한다.

## 1. 화면·입력·시간

- 기준 게임 화면 390×844 CSS px, 모바일 세로 9:16. 작은 기기는 높이를 늘리되 게임 월드의 시야를 줄여 난이도를 높이지 않는다. 데스크톱의 기획툴은 세로 미리보기와 양쪽 설정 패널을 제공한다.
- 첫 바퀴 기본 캐릭터는 루온 3.5등신. 리아·기존 비율도 같은 충돌 캡슐과 규칙으로 선택 가능. 외형 비율로 사거리·피격 면적을 바꾸지 않는다.
- 왼쪽 아래 이동 원판: 반경 52px, 사각 영역 120px, 데드존 0.12, 최대 입력에서 4.5m/s. UI가 먼저 포인터를 소비한다. 포인터가 화면 밖으로 나가거나 focus를 잃으면 이동·누른 버튼을 해제한다.
- 키보드 WASD/방향키 이동, Space 주 행동, E 보조 행동. 터치에서도 이동+행동을 동시에 수행할 수 있어야 한다. 건물·카드·메뉴 선택이 배우 이동으로 전달되면 안 된다.
- p01 궁극기/시설은 상황 UI, p02는 오른쪽 시선 드래그, p03은 기본 이동만, p04는 가로 드래그다. 추가 행동 버튼은 최대 2개. 구 지휘/굴착/러너 행동을 기본 HUD에 넣지 않는다.
- 60Hz 고정 게임 틱, 렌더는 장치에 따라 30/60fps. 프레임 수와 피해·이동·쿨다운을 연결하지 않는다. 숨김·포커스 상실·카드 선택·일시정지에서는 게임 시간이 멈춘다. 재개 시 누적 시간을 한꺼번에 처리하지 않는다.
- 결과 판정은 같은 틱에서 실패 조건을 먼저 확인하고, 살아 있는 상태의 목표 충족을 승리로 처리한다. 목표 완수와 사망이 동시에 일어나는 경우를 테스트한다. p04는 인간HP 대신 정화 경계 통과가 실패 조건이다. 같은 틱 경계 접촉과 마지막 처치가 겹치면 실패를 우선한다.

| 적 표적 갱신 | 가까운 적 10Hz, 멀리 있는 적 2~5Hz. 이동과 충돌은 고정 틱 |

피해 계산: `기본 피해 × 무기 레벨 계수 × 게임의 공격 배율 × 속성/방어 계수`. 방어 감소는 HP에 적용하며 렌더 스케일로 계산하지 않는다. 지속 피해는 0.5초 간격으로 예약하고 프레임마다 중첩하지 않는다. 방어·내성을 합친 피해 계수는 0.15 이상으로 두되, 보스 단계의 명시적 무적은 예고와 종료 시점을 가진 별도 상태다.

피해의 출처·대상·투사체ID·틱을 기록한다. 직접탄은 대상마다 1회, 범위탄은 폭발마다 각 대상 1회. 번개는 같은 연쇄에서 같은 대상 재방문 금지. 관통탄은 맞은 대상 집합을 유지한다. 벽·방패·서로 다른 고도의 대상을 건너뛰어 맞히지 않는다.

Lv 피해 계수 `[1,1.25,1.6,2,2.5]`, 쿨 계수 `[1,1,0.95,0.9,0.85]`. 이속+10%/레벨, 쿨-10%/레벨, 폭발반경+15%/레벨, 최대 HP+20/레벨. 쿨 패시브는 0.7배 아래로 내려가지 않는다. HP 선택은 늘어난 최대 HP만큼 현재 HP도 회복한다. 반경 배율은 면적 배율과 구분한다.

기존 `skills.json`의 모양·색·속도·궤적과 FX를 재사용하고, 피해·쿨은 새 게임 데이터로 분리한다. 원본 프리뷰의 피해 1·4·5를 그대로 가져오지 않는다. 폭탄과 투석기는 **느린 범위 공격**, 속사와 발리스타는 **빠른 직접/관통 공격**으로 구분한다.

### 애니메이션과 무기 보이기

- `PlayCharacter`의 로딩·SkeletonUtils.clone·AnimationMixer를 기반으로 한다. 입력·이동·상체 사격 상태는 분리한다.
- 정지속사=`shoot`, 단발/바주카=`shoot2`, 이동속사=`walk_shoot`, 이동폭탄=`walk_throw`, 무기를 들고 이동=`walk_gun`. 실제 클립을 먼저 재생해 의미가 다른 모델은 매핑을 교정한다.
- `gun`, `gunL`, `bomb`, `forearm.L/R` 노드는 현재 두 3.5등신 GLB에서 확인됐다. 이름만으로 총구 방향을 가정하지 말고 소켓의 로컬 축과 위치를 검사해 설정 파일에 저장한다.
- 발도/납도는 `draw`, `holster`, `draw_launcher`, `holster_launcher`. 쌍권총 사용·idle 중 큰 총은 후면 등 위치에 착용. 바주카 사격 시 손에 옮기는 동안 총구가 순간이동하지 않게 한다.
- 기존 머리 끝·귀·꼬리 보조 동작을 유지하고 상태 전환 때 리셋 점프를 방지한다. 속사 16발마다 전신 사격 클립을 새로 시작하지 않는다. 자세 루프+총구 FX 이벤트를 분리한다.
- 팔·상체 의상은 현재 본/부모 관계를 유지한다. 총구 섬광은 발사 노드의 월드 행렬에서 생성하고, 후면 카메라에서도 총보다 앞으로 튀어나온 실루엣이 보여야 한다. 색만 밝히는 사각 판으로 대체하지 않는다.

## 3. 카드와 성장

레벨업 시 유효 후보 3개를 중복 없이 제공한다. 장비 슬롯이 찼으면 새 무기 후보를 빼고 소유 무기 강화·패시브를 보여 준다. 전부 최대면 회복 20 또는 조각 보상으로 채운다. 선택 화면이 열리면 적·투사체·오염·카메라 이동 시간을 멈춘다. 선택 클릭을 다음 게임 입력으로 전달하지 않는다.

무기 가중치 기본 1, 이미 소유한 무기 강화 2, 아직 없는 진화 짝 패시브 1.5. 무기Lv5+짝 패시브Lv1 이상이면 다음 상자에서 진화 선택을 우선 제공한다. 상자가 없어서 진화가 영원히 막히지 않도록 p03 마지막 150~270초 사이 진화 후보를 레벨업 풀에도 허용한다. 진화는 같은 슬롯을 교체한다.

상세 구현은 [11 성장·연출](11_스킬성장_전투연출_Codex.md)을 따른다. 추가12패턴은 기존 외형을 재사용하며 M3에 구현 완료한 후보만 공개한다.

진화 4종: 불로켓→불기둥(기본탄+경로 폭 1.4m, 길이 8m, 4초 지속, 초당 24), 번개유도→3대상 추가 연쇄(주탄+후속3체 각0.6피해), 얼음로켓→얼음창 4개 회전(반경 2.2m, 대상별 0.5초 타격 간격, 12피해), 폭탄→3발 융단(서로 다른 3지점, 각 원래 피해×0.6). 이 수치는 기존 진화 그림·FX와 맞춰 검증한다. 회전창은 충돌 틱과 시각 회전이 같은 각도를 사용한다.

## 4. 적 AI·경로·혼잡

종류별 역할·HP·속도·피해·예고·공격간격·크기·방어·점수·스폰 구역을 `enemy-catalog.v2.json`에 분리한다. 같은 종류의 _2 모델도 행동/능력 수치를 다르게 둔다. 49종을 하나의 체력·속도 템플릿으로 렌더만 바꾸지 않는다.

이동 상태: Spawn→Approach→Telegraph→Attack→Recover, 피격/사망은 별도. 빠른 추적·원거리 거리 유지·돌진·분대 우회·비행·방패·배회를 행동 모듈로 구현한다. 바닥 공격 예고는 공격 전에 실제 충돌 범위에 표시한다.

**자유 추적 적의 한 점 집결·한 줄 행렬 금지.** p04의 pathPolicy=chain은 의도된 연결 편대이므로 접근 슬롯/분산 AI를 적용하지 않는다. 자유 추적은 표적 둘레의 접근 슬롯, 경로는 스플라인별 횡방향 차선과 개체 간격을 쓴다. 반경 합의 1.05배를 최소 중심 거리로 목표 삼고 근처개체 밀어내기를 적용한다. 막사 앞 대기열은 2~3개의 짧은 줄로 나누며 길을 막는 적은 전투 중 실제 블로킹 슬롯에 선다. 시설/수레 주변에서도 공격 위치를 둘레에 배정한다.

2~3종을 겹쳐 스폰할 때 각 그룹의 start·interval·route를 독립 예약한다. 배열의 첫 종을 모두 낸 뒤 두 번째 종을 내는 루프를 쓰지 않는다. 모든 적을 매프레임 전체 비교하지 않고 2m 공간 해시를 사용한다. 밀집 때문에 경로가 막히면 1초 후 다른 접근 슬롯을 찾고,3초 이상 움직임 없는 개체는 재경로한다. 낭떠러지로 밀어내서 처리하지 않는다.

### 구도·생활·환경

- 최초 구도는 전경 비행선·선착장·사람, 오른쪽 메인집·펫 마당, 후경 4채와 바다의 깊이. VILLAGE03 카메라가 16:9이므로 세로에서는 중심을 다시 프레이밍하고 집 선택 시 해당 섬으로 1.2초 이동한다. 무조건 좌우를 잘라 5채가 사라지게 하지 않는다.
- 카메라 제스처는 로비 제한 회전 ±20°와 줌 0.8~1.25. 자유 궤도는 기획툴 검수 모드에만 둔다. 메뉴를 연 상태에서는 카메라가 손가락을 따라 움직이지 않는다.
- 주민은 이동 가능한 마당·집 앞·다리를 내비로 잇는다. 펫은 HomeStay40~120초→목적지 선택→Walk→Pause/Sit8~25초→Return의 생활 루프. 달리기는 먼 이동 중 짧게 사용하며 집 문·다리를 무시하지 않는다.
- 구출되지 않은 펫은 로비 실제 주민으로 미리 배치하지 않는다. 도감 미리보기의 잠금 실루엣은 허용한다. 구출 후 집/마당의 residenceId와 연결한다.
- 마을 24시간은 환경 표현이다. 기본 12시, 자동 순환 15분=24시간, 기획툴은 슬라이더·배속·고정시간을 가진다. 새·구름·태양·달·폭포·부유 코어·비행선 항로·바다 파도는 기존 코드를 이식한다.
- 부유는 섬 부모변환±0.08m, 느린 위상차. 주민·내비·폭포·다리 양끝이 같은 변환을 따라야 한다. 물리 지형을 개별로 흔들어 접속이 끊기게 하지 않는다.
- 파도는 저주파 큰 파+짧은 블록 잔물결·제한된 포말. GPU 변위/인스턴싱 재사용, 큐브 수천개 CPU 갱신 금지. 새는 소규모군 3~8마리, 원거리 저빈도 갱신.
- 전투는 미션별 조명을 고정해 예고·바닥을 읽을 수 있게 한다. 밤의 얼굴 그림자를 강하게 만드는 조명과 과도한 청록 emissive를 피한다. 조명은 두 캐릭터·두 비율을 같은 기준으로 검사한다.

출항: 카드 상세에서 미션 확정→필요 자산 비동기 로드→비행선 4초 출항(1초 뒤 건너뛰기 가능)→준비 완료 후 플레이. 로드 실패면 오류/재시도/로비 복귀, 게임 타이머는 시작하지 않는다. 정화 결과 귀환 후 펫 등록은 idempotent한 구출 이벤트로 1회만 실행한다.

## 6. 카드 미션 로비와 결과

카드 3:4, 중앙 1장+양쪽 다음/이전 일부. 상단 지역·바퀴 n/5·구출 진척, 중앙 카드의 3D 렌더 이미지, 하단 목표·예상시간·게임 특징·클리어 별·출항. 잠금은 이유와 이전 필요 미션을 보여 준다. 카드 썸네일은 실제 3D 장면에서 캡처하며 기존 2D 게임 스프라이트를 본체로 쓰지 않는다.

잠금 해제는 현재 순서의 앞 미션 정상 성공 뒤 1회. 새 캠페인은 지역별4카드, 총20카드 제안이며 p04 정상 성공 후 지역 펫의 구출 이벤트를 1회 지급한다. 구 s01~s10 저장은 보관한다. 다시 플레이해도 펫·다음 바퀴가 중복 지급되지 않는다. 포기/테스트 성공은 개방과 구출에 영향을 주지 않는다.

결과는 win/lose/abort로 구분한다. 목표 실적·플레이 시간·받은 피해·무기 빌드·미션별 지표를 보여 주고, 재도전/다음 카드/로비 버튼을 둔다. 실패 이유는 인간 체력0, 코어 파괴, 대열의 정화 경계 통과 등 규칙에 맞춘다.

별: 정상 승리 1개+게임별 도전 조건 2개. 테스트·무적·수치수정·자동 조작 결과는 별·구출·캠페인 저장에 반영하지 않는다. 보조 난이도를 사용한 정상 플레이는 도전별 보조사용 조건에 따라 성적에 assist를 표시한다.

## 7. 기획툴의 제작 구조

| 탭 | 보기/편집 | 실제 실행 |
|---|---|---|
| 전체 기획 | 컨셉·흐름·지역·게임 연결·결정 이력 | 캠페인 연결 실행 |
| 로비 | 집·주민·펫·카메라·시간·메뉴 링크 | 실제 로비만 실행 |
| 미션 카드 | 순서·개방·텍스트·맵·구출 대상 | 카드만 실행/테스트 저장 프로필 |
| 게임 | p01~p04 각 규칙·무기·적·목표 | 실제 3D 독립 플레이 |
| 밸런스 | 웨이브·비용·피해·경제·성적 조건 | 고정seed 비교·입력 리플레이 |
| 리소스 | 파일·소켓·클립·LOD·맵 내비·충돌 | 실제 모델과동작 뷰어 |
| 검수 | 플레이 기록·실패 이유·성능·스크린샷 | 기록된 설정 재실행 |

실행 미리보기는 제안 `arcade-play.html`의 동일한 GameSession을 사용한다. 기획 UI와 게임 HUD는 별도 DOM 계층이다. 빌드한 게임은 기획툴 밖에서도 같은 scene·config·snapshot으로 실행 가능해야 한다.

숫자 수정 흐름: 편집 초안→범위 검사→변경 전/후 표시→적용→RunSnapshot 생성→실행→기록→기준판 승격. 저장과 플레이 적용은 별 버튼이다. 초안 저장만으로 진행 중 캠페인의 적 체력이 바뀌면 안 된다.

라이브 반영 가능: damage,cooldown,spawnInterval,빛 강도. 다음 틱 이후의 이벤트부터 적용하며 기존 투사체는 생성 당시 값 유지. 재시작 필요: map,route,rulesetId,pathPolicy,actor sockets,capacity,스폰 구성. 변경된 런은 원래 결과와 분리하고 원복/재시작을 지원한다.

필수 조절 항목: 인간HP·속도·배율·무기레벨·쿨·범위·펫; 적별HP·속도·간격·예고·내성·길·무게; 건물별비용·레벨·공속·타격형·대공·범위·블로킹; 게임별목표·시간·성적·이동정책·마디체력·경로·경계·탄수/연발/관통; 맵카메라·시야·충돌·보행; 로비환경·메뉴; 구출/개방 조건.

## 8. 저장·실패 복구

- `campaign.v2`: 미션별 최고별/개방·동물·선택 배우. localStorage 초기 구현, 추후 저장 어댑터 교체 가능.
- `planner-draft.v1`: 편집중 설정과 변경 이력. 서버 저장 실패는 현재 초안을 남기고 재시도 안내.
- `runlog.v1`: seed,configHash,buildId,입력 틱,사건,성능,결과. 큰 로그는 IndexedDB에 저장하고 JSON 내보내기.
- 진행 중 게임은 재접속 자동 성공 처리하지 않는다. v1은 미션을 처음부터 다시 시작하고 이전 완료 미션은 유지한다. p04 개발용 이어하기는 testOnly로 구분한다.
- 저장 읽기에서 버전·무결성을 검사한다. 손상 시 백업 복원/새 프로필을 선택하게 하고 기존 파일을 무조건 지우지 않는다.

사용자에게 보여 주는 문구에는 엔진·리소스 경로·디버그 상태를 노출하지 않는다. 개발 설정·메모리·틱·개체ID는 기획툴 패널에 표시한다. 버튼 최소 44px, 색+형태로 속성/예고 구분, 카메라 흔들림·플래시 감소 설정을 제공한다.

## 9. 대표 4종의 공통값 적용 범위

p01/p02/p03은 인간 HP·쌍권총/바주카·동행 펫을 공유한다. p02는 조준 정책을 시선 원뿔+가시선으로 바꾸고 p04는 인간HP/자유이동을 쓰지 않으며 chain-defense 전용 무기·좌우 이동·경계 실패를 사용한다. 전용 수치는 02문서와 rulesets.v2가 우선이다. 공통 표를 재사용한다는 말은 모든 게임에서 동일한 HUD·숫자를 강제한다는 의미가 아니다.

카드 풀은 profile/ruleset과 슬롯 종류로 필터한다. p01 시설만은 시설 카드, p04는 탄수/연발/관통/전용보조 카드, p03은 무기/패시브/진화다. 전부 같은 카드 서비스가 유효 후보 검사·3택·정지·확정·재개를 맡는다.

정화는 승리 결과의 월드 전환과 지역 진행이다. 구 g09의 면적70% 승패는 기본판에 없다. 오염형/정화형 GLB 두 개를 겹쳐 z-fighting을 만들지 않고, 정적 지형은 재질/색 전환 또는 안전한 장면 교체로 연출한다. 동일 지형의 충돌/내비를 유지하고 배우가 바닥으로 떨어지지 않게 한다.
