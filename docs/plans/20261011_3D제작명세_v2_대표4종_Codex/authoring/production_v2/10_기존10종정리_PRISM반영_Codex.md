# 기존 10종 정리와 PRISM 구조 반영

작성: Codex · 2026-10-11

## 1. 변경의 이유와 처리 경계

사용자는 대표 게임을 후더덕형·FPS 모드·탕탕/뱀서형·첨부 Cell형의 4종으로 지정했다. 이들을 공통 표와 구조로 만들고 싶다는 방향에 맞춰 별도 무리 지휘·굴착·러너 기술을 첫 범위에서 뺀다. 구 10종은 독립 제작 의무에서 내려놓되 자산과 설계는 보존한다.

이 패키지는 문서/초기 데이터만 바꾼다. `planner/data.json`의 실제 메뉴와 과거 저장은 아직 그대로다. 제작 AI는 아래 마이그레이션을 자신의 첫 계획에 등록하고 정본·UI·저장을 함께 바꾸어야 한다.

## 2. 구 ID 처리표

| 구 ID | 활성 대표에 대응 | 메뉴 처리 | 남길 재사용 대상 |
|---|---|---|---|
| g01 | p03 | 대표 카드로 교체 | 생존·XP·카드·진화·보스 |
| g05 | p01 / p02 | p01 대표, p02 파생 대표 | 시설·웨이브·경제·코어 |
| g07 | p01/laneDefense | 대표 메뉴에서 흡수 | 고정 길·분산·막사·대공·빠른/범위 타격 |
| g08 | 모든 규칙 계열/bossEncounter | 독립 카드 흡수 | 패턴·예고·단계·보스 도감 |
| g02 | p02/p03 후속 roomVariant | 보관/후속 표시 | 6종 실제 방 GLB, 문·회복·방 편성 |

메뉴의 ‘보관 기획’ 탭에서 구 문서를 열 수 있게 한다. 사용자가 모델을 검수하는 유닛/캐릭터/펫 툴은 이 목록 정리와 별개로 유지한다. 완료한 캐릭터를 다시 만들거나 삭제하지 않는다.

## 3. 기획 정본을 바꾸는 순서

1. `planner/data.json`과 저장 export를 날짜 백업한다. 원본을 보존하고 변경 초안을 따로 만든다.
2. `gameProfiles` p01~p04와 `rulesets` 3개를 새 스키마로 추가. 구 games/g01~g10은 legacy 섹션으로 옮긴다. 단순 이름 치환 금지.
3. 새 카드 r01-p03 등의 20개를 campaign.v2로 생성하고 지역 설명·목표·앞뒤 대사·구출 시점을 수정한다.
4. 과거 별/미션 기록은 legacyResults에 보관. 구 g01 성공은 새 p03 도전 가능, g05/g07 성공은 새 p01 도전 가능의 안내로 활용하되 수치와 규칙이 달라 새 3별을 자동 지급하지 않는다.
5. 구출 펫·캐릭터 선택·비율은 유지. 중복 구출 이벤트를 petId 기준으로 막는다.
6. 메뉴·문서 export·설정 편집·실제 실행이 같은 profileId/rulesetId를 표시하는지 검수한다.

자료가 손상되면 백업/새 프로필 선택을 제공한다. 새 형식으로 읽기 실패했다는 이유로 구 진행도를 삭제하지 않는다.

## 4. 클로드의 PRISM 분석을 어떻게 사용하나

읽은 문서: `docs/plans/20261011_PRISM구조분석_Claude.md`. 분석 대상 빌드 `docs/PRISM_SQUAD_v2_build_20260606_1908/`에는 47개의 본편 CSV가 있다. skill_config, levelup_rule_config, formation_spawn_config 등 실제 표의 헤더와 행을 재확인했다. 이 턴에서 PRISM 전체 플레이를 다시 실행한 것은 아니다.

가져갈 것은 **표의 분리 구조·발사 방식·카드 규칙·역할/밸런스 표본**이다. PRISM의 2D 스프라이트, 과금, 장비 영구 성장, 광고 부활, 독립 퍼즐/타이쿤 이벤트는 첫 범위에 가져오지 않는다. 빌드 JavaScript를 소스인 것처럼 편집해 핵심 런타임으로 삼지 않는다.

| PRISM 표/생각 | v2 대응 | 제작 원칙 |
|---|---|---|
| event_minigame_host_config | profiles.v2.json | 등록/노출/뷰/규칙 계열을 표로 관리 |
| combat_tuning, skill_runtime_config | common.v2 + parameter dictionary | 값·단위·설명·범위·적용 시점 표시 |
| skill_config + projectile_config | skills.v2 + projectile behavior | 스킬/발사 방식/외형을 분리 |
| skill_level_config | level curves | 수량·연발·공속·피해를 별도 필드로 계산 |
| skill_evolution_config | evolution table | 무기+패시브 조건, 같은 슬롯 대체 |
| wave/rush/formation | spawn plans | 웨이브·급습·편대를 같은 예약 시스템에 넣기 |
| levelup_rule_config | card policy | 3택, 진화 최대 1장, 진화 우선, 중복/무효 후보 제거 |
| stage/challenge | mission/round override | 기본 표를 수정하지 않고 합성 |
| boss_pattern_config | boss state/pattern records | 예고·방향 잠금·타격·회복·단계를 표로 관리 |

원본 픽셀/프레임은 그대로 복사하지 않는다. 수스 기준은 m/sec/HP/tick60. 클로드의 27px/m은 참고 변환 제안이며, 실제 모델 캡슐 0.35m와 PRISM 반경을 검수해 확정한다. 데이터 어댑터가 없는 임의 단위 혼용을 허용하지 않는다.

## 5. 같은 표로 가능한 부분과 추가 모듈

공유: 배우·무기·탄·피해·속성·적 카탈로그·보스·카드·스폰 예약·성적·저장·성능. 달라지는 것은 입력, 카메라, 이동 정책, 목표 정책, 편대 정책, 시설 사용 여부다.

FPS는 p01 규칙을 상속하지만 1인칭 가까운 무기·팔, 시선/총구 차이, 엄폐 가시선, 뒤쪽 경고, 멀미 감소를 구현해야 한다. 모델·테이블 재사용과 표현 작업량을 구분한다. Cell형은 자유 추적 AI 대신 연결 경로와 마디별 체력/제거를 추가한다. 이것을 HP·카메라 숫자만 바꿔 완성된다고 처리하지 않는다.

데이터 ID는 역할이다. profileId가 p02라고 피해 함수를 새로 만들지 않는다. `viewPolicy`와 `controlPolicy`는 `rulesetId=base-defense`를 바꾸지 않는다. 같은 월드 입력을 녹화해 p01/p02 카메라만 바꿔 재생하면 피해/승패 로그가 같아야 한다. 실제 조작/조준 정책을 바꾸면 명중률 차이는 정상이며 별도 측정한다.
