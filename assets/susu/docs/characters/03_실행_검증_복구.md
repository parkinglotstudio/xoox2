# 실행·검증·복구
작성: Codex · 2026-09-27

## 1. 현재 실행 환경

- Windows 로컬 프로젝트 `C:\xoox`.
- Blender: `C:\Program Files\Blender Foundation\Blender 5.2\blender.exe` (확인 버전 5.2.2).
- Node: `C:\Program Files\nodejs\node.exe`.
- Python 보조 스크립트: `C:\Python314\python.exe`. 모델링 bpy는 Blender 내장 Python으로 실행한다.
- package.json: three.js/@types 0.185 계열, Vite 5.4 계열, TypeScript.
- GLB 브라우저 경로는 `/tools/unit_lab/...`. Vite의 data 공개 경로 설정을 사용한다.
- file://로 HTML을 직접 열지 않는다.

서버가 꺼진 경우 프로젝트 터미널에서 실행:
```powershell
Set-Location C:\xoox
npm run dev -- --host 127.0.0.1 --port 5179 --strictPort
```
이미 실행 중이면 같은 포트의 서버를 또 시작하지 않는다.

## 2. 기본 사용

유닛 랩 왼쪽에서 루온/리아와 기존형/3.5등신을 고른다. 오른쪽 이동·전투·무기·표정 메뉴에서 동작을 선택한다. 클릭 직후에는 이전 동작에서 짧게 혼합되므로 기준 자세를 비교할 때 전환이 끝난 뒤 일시정지한다.

정면/후면 버튼, 마우스 회전·확대, 속도 조절을 사용할 수 있다. 보기·조명에서 원본 스프라이트/성능 수치/끝머리/디테일 광원을 켠다. 기본 화면에는 모델 하나를 표시한다.

체형 비교는 한 캐릭터의 기존형/3.5등신 두 개를 동일 조건으로 표시한다. 좌우 라벨의 링크는 해당 모델의 유닛 랩으로 연결한다. 과거 `wanderer-d-sprite-tool.html`은 새 비교 화면으로 이동한다.

## 4. 다시 제작하는 순서

현재 사용본을 먼저 백업한다. 아래 명령은 실제 모델 파일을 갱신한다. 현재 머리 보정처럼 일부만 바꾸려면 해당 범위용 스크립트를 사용한다.

### 기존형 전체 재생성
```powershell
Set-Location C:\xoox
& 'C:\Program Files\Blender Foundation\Blender 5.2\blender.exe' -b -P scripts/unit_lab_characters/rebuild.py -- --character RUON
& 'C:\Program Files\Blender Foundation\Blender 5.2\blender.exe' -b -P scripts/unit_lab_characters/rebuild.py -- --character RIA
```

rebuild.py는 기존 제작기를 실행하되 ART 출력 경로를 프로젝트 내부 character/A 또는 D/source로 제한한다. 리아는 refine_d08.py의 찡그림 선 보정까지 이어서 실행한다. 원래 제작기 단독 실행은 과거 외부 아트 폴더 경로를 포함하므로 이 래퍼를 진입점으로 사용한다.

이번에는 얼굴·몸·애니를 유지하기 위해 전체 재생성 명령을 실행하지 않았다. 래퍼는 경로 치환과 Python 구문을 검사한 재현용 진입점이며, 전체 재생성 뒤에는 아래 검수 절차를 다시 수행한다.

### 3.5등신 재생성
```powershell
& 'C:\Program Files\Blender Foundation\Blender 5.2\blender.exe' -b -P scripts/unit_lab_characters/build_ruon.py -- --head-units 3.5
& 'C:\Program Files\Blender Foundation\Blender 5.2\blender.exe' -b -P scripts/unit_lab_d_sprite/build_sprite.py -- --head-units 3.5
```

먼저 기존형을 확정한다. 비율 제작기는 프로젝트 내부 source를 우선하며, 없으면 과거 아트 원본 경로를 사용한다. 몸/머리/모프/본/손 목표를 함께 바꾸므로 GLB만 단순 비율 변형하지 않는다.

D sprite 제작기의 기본 인자는 과거 4.4등신이다. 현재 사용본을 만들 때 반드시 `--head-units 3.5`를 명시한다. 4.4등신은 보관용이다.

### 이번 정수리만 재현
```powershell
& 'C:\Program Files\Blender Foundation\Blender 5.2\blender.exe' -b -P scripts/unit_lab_characters/refine_ruon_crown.py
```

이 스크립트는 `docs/asset_backups/20260927_RuonCrown_Codex/`의 **이번 수정 직전 스냅샷**을 입력으로 쓴다. 이후 새 의상·새 동작을 만든 다음 같은 스냅샷을 무심코 재사용하면 후속 변경을 되돌리게 된다. 다음 보정에서는 새 백업을 만들고 입력 경로를 갱신한다.

### 고양이
```powershell
& 'C:\Program Files\Blender Foundation\Blender 5.2\blender.exe' -b -P scripts/unit_lab_cat/build_cat.py
```

출력은 프로젝트 pets/block_cat에 저장된다. `-- --render`를 붙이면 제작기의 정지 렌더도 생성한다.

## 6. 검수 명령과 근거

```powershell
node node_modules/typescript/bin/tsc --noEmit --target ES2022 --module ESNext --moduleResolution Bundler --skipLibCheck --strict src/tools/unitLabTool/main.ts src/tools/characterCompare/main.ts src/tools/unitLabA/main.ts src/tools/unitLabD/main.ts
node scripts/unit_lab_characters/verify.mjs
node scripts/unit_lab_characters/verify_crown.mjs
node scripts/unit_lab_characters/verify_handoff.mjs
```

verify.mjs는 네 활성 모델·18클립·모프·새 루온 접지 표본·선택/정지/유닛 전환을 검사한다. 현재 Playwright 경로는 로컬 Codex 번들 경로를 사용하므로 다른 PC에서는 require 경로를 조정한다. 검증 브라우저에서만 HMR을 차단한다.

verify_crown.mjs는 수정 직전 GLB와 수정 후 GLB를 같은 조명/각도로 비교하고 모든 클립 키 값 차이를 검사한다. 다른 수정 기준에서는 백업 URL을 같이 바꾼다.

verify_handoff.mjs는 실제 유닛 랩에서 루온 두 체형의 새 정수리 버전과 본/동작/좌표, 걷기·달리기·사격 전환 및 로드 오류를 확인한다.

과거 verify_d06/d07/d08, verify_a01, verify_lighting, verify_face_appearance, verify_muzzle_fx 및 고양이 verify_preview/verify_transitions는 그 단계의 증거와 검수법이다. 이전 A/D/DS 버튼 ID를 직접 찾는 스크립트는 현재 네 선택지에 맞춰 수정해야 한다. 과거 스크립트가 모두 최신 UI와 호환된다는 뜻은 아니다.

## 7. 백업과 복구

### 미사용 시안/이전 툴
- `docs/asset_backups/20260927_characters_Codex/unused_variants_and_previous_tool.zip`.
- 19파일, 파일별 SHA256 및 ZIP CRC 검사.
- manifest.json의 path가 프로젝트 기준 복구 위치다.
- 원본 호환 파일은 남아 있어도 활성 목록에는 네 가지뿐이다.

### 정수리 수정 직전
- `docs/asset_backups/20260927_RuonCrown_Codex/`.
- RUON/RUON_35의 GLB·BLEND, 수정 전 제작기·metrics, SHA256.
- preservation_check.json은 머리 외 메시 보존 결과다.
- 복구할 때 GLB·BLEND·제작기·metrics를 같은 버전으로 맞춘다. 캐시 버전과 catalog도 같이 확인한다.

### 초기 제작 코드
- `docs/characters/legacy_sources/`에는 외부 아트 폴더의 Python 제작 소스를 사본으로 보관했다.
- 당시 원본 자산·텍스처·렌더는 외부 폴더와 inventory에 위치를 기록한다.
- 사본 코드의 절대 경로는 역사적 실행 환경을 가리킬 수 있다. 현재 제작은 scripts/unit_lab_*를 사용한다.

복구 전에 현재 버전을 다른 날짜 폴더로 보관하고, 필요한 파일만 manifest와 대조해 복사한다. 다른 에이전트 파일을 포함해 프로젝트 전체를 덮어쓰지 않는다.

## 8. 알려진 한계와 이어받을 때의 주의
- 한 장의 시안에서 보이지 않는 부분은 모델링 해석이다. 모든 시점에서 그림과 한 치도 다르지 않다는 보장은 하지 않는다.
- 조명·노출·얼굴 셰이더를 다르게 적용하면 같은 GLB도 색이 달라진다.
- 고정 블록 모델의 셀 크기는 제작 시 확정된다. nativeBlocks 캐릭터의 일반 블록 크기 슬라이더가 비활성인 이유다.
- 고해상도 정수리는 삼각형 수를 늘린다. 기존형/3.5등신에 같은 토폴로지를 사용하며 이번 수치는 최종 metrics를 본다.
- 현재 모델은 클로즈업 프리뷰를 포함한 제작 자산이다. 다수 배치·저사양 모바일·LOD·압축은 별도 측정이 필요하다.
- 무기 발도/납도 클립과 툴 버튼은 존재한다. 본편의 장비 상태 머신·피격·발사체·AI 연결 여부는 해당 게임 담당 코드에서 별도 확인한다.
- 수정된 기존형을 3.5등신에도 적용하려면 두 산출물을 함께 갱신한다.
- 셰이더 수정 시 기존 onBeforeCompile과 customProgramCacheKey 연결을 유지한다. 캐릭터 전환 시 재질·믹서·FX 해제를 보존한다.
- VoxelCloud의 기존 API와 units_free.json은 다른 도구에서도 사용하므로 임의로 바꾸지 않는다.
- 공유 상태판은 자기 행만 수정하고 기존 기록을 보존한다. 그룩 지시 파일/작업 목록은 더 이상 확인하지 않는다.
